# Бэкенд EduAgent АЦР

Бэкенд реализует чек-лист команды и использует `CourseProgram` и функции
из `ml/`. Отдельная конкурирующая схема курса не создаётся.

## Запуск

Команды выполняются из корня репозитория. Нужен Python 3.10 или новее;
проверка разработки выполняется на Python 3.12.14 в Windows.

Windows PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload --port 8000
```

Linux или macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
cp -n .env.example .env
.venv/bin/python -m uvicorn backend.main:app --reload --port 8000
```

Откройте [Swagger UI](http://localhost:8000/docs). Все операции можно выполнить
через `Try it out`. [OpenAPI](http://localhost:8000/openapi.json) описывает
формат запросов и ответов. `/api/health` проверяет доступность HTTP API;
подключение модели проверяется отдельным реальным запросом.

## Режимы ML

- `ML_MODE=demo` использует демонстрационные структуры существующих ML-навыков.
  В ответах присутствуют `execution_mode: "demo"` и предупреждение.
  Учебное содержание этих структур требует доработки ML-разработчиком.
- `ML_MODE=cloud` использует `CLOUD_RU_API_KEY`, `CLOUD_RU_BASE_URL` и
  `CLOUD_RU_MODEL`. Адрес должен быть HTTPS в домене Cloud.ru. Нужен точный
  доступный ID модели из выданного проекта; пример ID из старого README
  не принимается за подтверждение текущей доступности.

Cloud-ошибка возвращается как 502, отсутствие настроек как 503, таймаут
как 504. В cloud-режиме отсутствует автоматический переход на демоданные.
Метрики токенов берутся из ответа SDK, а не из условного счётчика ML-демо.
Стоимость и экономия времени представлены как `null`, пока нет подтверждённого
расчёта. Вызовы навыков выполняются вне event loop, поэтому health и чтение
проекта доступны во время генерации.

## Порядок вызовов

### Анализ и референсы

`POST /api/projects/analyze` принимает `multipart/form-data`:

| Поле | Значение |
|---|---|
| `query` | Текст запроса методиста |
| `files` | Необязательные файлы; поле можно повторять |
| `project_id` | Необязательный существующий проект для повторного анализа |

Ответ содержит поля `ClarifyResponse`, `project_id`, `revision`,
`execution_mode` и `backend_warnings`. При нехватке сведений
`is_complete=false`, вопросов не больше пяти. Неуказанные часы не заменяются
скрытым значением 72.

Референсы ограничены пятью файлами по 10 МБ, общий извлечённый текст —
120 000 символами. DOCX читается вместе с таблицами и вложенными таблицами.
У PDF извлекается текстовый слой. Скан без текста требует OCR и возвращает
явную ошибку. Временный путь не строится из имени загруженного файла.

### Каркас

`POST /api/projects/skeleton`, JSON:

```json
{
  "project_id": "ID_ИЗ_АНАЛИЗА",
  "query": "Повышение квалификации по анализу данных на Python для сотрудников банков, 72 часа, очно-заочная форма, итоговая аттестация — защита проекта.",
  "template_type": "dpp_pk",
  "total_hours": 72,
  "clarifications": "Ответы методиста на уточнения"
}
```

Если анализ не вызывался, `project_id` можно опустить. Если файлы были
загружены, фронтенд должен передать ID из анализа — так референсы попадут
в тот же проект и последующие ML-вызовы. `template_type` и `total_hours`
можно опустить, когда они однозначно указаны в запросе. Ответ — поля
`CourseProgram` и метаданные бэкенда, статус `skeleton_ready`.

### Правки и утверждение

`PUT /api/projects/{project_id}/skeleton` принимает весь полученный каркас
или JSON с изменёнными полями. Передавайте `revision` из последнего ответа:

```json
{
  "revision": 1,
  "goal": "Согласованная методистом цель программы"
}
```

Вызывается балансировщик ML, затем проверяется арифметика. Отрицательные
часы, другой `project_id` и устаревшая версия отклоняются. Ответ имеет
статус `approved`. Правка каркаса очищает предыдущие тесты и слайды, чтобы
устаревшие материалы нельзя было скачать как актуальные.

### Полный комплект

`POST /api/projects/{project_id}/generate-content` разрешён после утверждения.
Во время работы `GET /api/projects/{project_id}` возвращает `busy: "generating"`.
После завершения статус курса равен `completed`, `busy` снова равен `null`.
При ошибке сохраняется утверждённый каркас. Повторный вызов для завершённого
проекта возвращает сохранённый комплект без повторной генерации.

Генератор вызывается по модулям, чтобы принадлежность слайдов была известна
без изменения `ml/schemas.py`. Тесты и семинары имеют устойчивые ID вида
`Q-1.1-1` и `SEM-1.1-1`; слайды в публичном JSON дополнены `module_id`.

### Точечная правка

`POST /api/projects/{project_id}/regenerate-part`, JSON:

```json
{
  "element_type": "topic",
  "element_id": "1.1",
  "instruction": "Добавить пример по обработке пропущенных значений",
  "revision": 4
}
```

Допустимые типы — `topic` и `test`. При правке темы обновляются связанные
тесты, семинары, слайды и список источников затронутого модуля. Другой
модуль и его оценочные материалы сохраняются. Часы и связи компетенций
этой операцией не меняются; для этого используется правка каркаса.

### Экспорт

`GET /api/projects/{project_id}/export/docx`, `/pptx`, `/gift`, `/csv`, `/json`.
Для DOCX/PPTX/GIFT/CSV нужен завершённый комплект. JSON доступен на любом
этапе. Необязательный параметр `?revision=4` защищает скачивание от смены
версии между просмотром и экспортом.

DOCX формируется отдельно для ДПП и ДООП из пользовательских образцов АЦР.
Приказ, ФИО и подписи остаются пустыми. В таблицах добавлена колонка ИА,
чтобы аттестация учитывалась ровно один раз. PPTX содержит заметки лектора,
длинный текст разбивается на дополнительные слайды. GIFT использует UTF-8
и экранирование специальных символов. CSV — таблица для обработки;
предназначенный для импорта Moodle формат — GIFT.

## Единый эндпоинт жюри

`POST /api/v1/evaluate` использует тот же процесс:

1. `{"query": "..."}` создаёт каркас или возвращает уточняющие вопросы.
2. `{"action":"approve","project_id":"...","approved":true}` утверждает
   уже полученный каркас. Необязательное поле `course` содержит правки.
3. `{"action":"generate","project_id":"..."}` создаёт материалы.

Дополнительные действия — `analyze`, `regenerate`. Endpoint не пропускает
утверждение методистом. Финальный протокол автоматической проверки нужно
сверить с контрактом, который выдаст жюри.

## Хранение и ошибки

По умолчанию JSON записывается в `data/projects/{project_id}.json`.
Файл содержит курс, анализ, референсы и серверные метаданные. Сохранение
атомарное, версия увеличивается при каждой записи. Папка задаётся
`PROJECT_DATA_DIR`; относительный путь отсчитывается от корня репозитория.
Локальные данные и `.env` не попадают в Git.

Рассчитано на один процесс Uvicorn. Для нескольких worker-процессов нужны
общее хранилище и межпроцессные блокировки. Ошибки имеют вид
`{"detail":{"code":"...","message":"..."}}`; 409 означает необходимость
уточнения, утверждения или обновления версии, 422 — некорректные данные.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
```

Границы фактически выполненных проверок и оставшаяся приёмка описаны
в [чек-листе](../docs/BACKEND_CHECKLIST.md).

Для отдельной проверки реального HTTP-сервера:

```powershell
.\.venv\Scripts\python.exe scripts/verify_backend.py
```

Скрипт запускает свой локальный сервер строго в `demo`, загружает DOCX и
PDF, выполняет утверждение и генерацию обоих типов программ, скачивает
все форматы, проверяет правку темы и останавливает процесс. Результаты
и файлы сохраняются в `data/verification/`. Реальные платные модели при
этом не вызываются.
